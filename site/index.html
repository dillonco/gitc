A git client the size of a git client.

gitc draws your whole commit graph, stages by the hunk, and hands every operation to the git binary already on your machine. The rest is one Rust core and the webview your OS already ships. No bundled browser, no background daemon.

Under the hood

It runs git. Literally.

The Rust core doesn't reimplement git — it drives the git CLI you already have installed and trusts its answers. Whatever your hooks, config, and credential helpers do on the command line, they do here too.

  • Svelte UI in a native webview via Tauri, so the app stays small and starts fast.
  • Every mutation is a real git command, so it all lands in your reflog.
  • The git layer is covered by integration tests that run real git against real repositories.
What's in the box

Dense where it counts, quiet everywhere else.

One window, no tabs to babysit. The graph, the diff, and the working tree are always a glance apart, and everything below is in the app now, not on the roadmap.

  • 01

    The graph, drawn properly

    Lanes, merge edges, and ref pills for every branch and tag. Search the history by message, author, hash, or ref and jump straight to the commit.

  • 02

    Stage by the hunk

    Flat or tree view of the working copy, unified or side-by-side diffs, and stage, unstage, or discard at the hunk level.

  • 03

    Merges you can back out of

    A progress banner with continue and abort while a merge or rebase is in flight, and a conflict editor that shows base, ours, theirs, and your resolution. Nothing is written until you save.

  • 04

    Careful by default

    Pull is fast-forward only. Force-push always takes --force-with-lease. Destructive actions can be gated behind a confirmation, and that gate is a setting, not a lecture.

  • 05

    The rest of the toolbox

    Branches and remote tracking, tags, stashes, worktrees, blame, per-file history, cherry-pick, revert, and reset — all reachable from the commit you're looking at.

  • 06

    Try it before you build it

    npm run dev:ui runs the whole interface in your browser against an in-memory demo repository. No Rust toolchain, and nothing touches a real repo.

Happy with lazygit or plain git? Keep them — gitc shells out to the same binary, so nothing about your setup changes. It earns its window when you're reading: a drawn graph you can scan, the diff beside it, hunks you can click. When the terminal is faster, use the terminal.

Get it

Clone, build, keep it.

$ git clone https://github.com/dillonco/gitc
$ cd gitc
$ npm install
$ npm run build
# → src-tauri/target/release/bundle/macos/gitc.app

You'll need Node and a Rust toolchain. npm run dev starts the app with hot reload; npm run check type-checks it.

Just want to poke at the interface first? npm run dev:ui runs it in your browser against an in-memory demo repo — no Rust toolchain needed.

Not building today? The source and the roadmap are on GitHub — issues welcome, especially "this broke on my repo."
